# Проектирование механизма отправки уведомлений о доставке

## Назначение проекта

Проект посвящён проектированию механизма обработки событий изменения статуса заказа и отправки PUSH-уведомлений пользователям маркетплейса.

События поступают от внешних систем через API. Маркетплейс принимает события, проверяет их корректность, обновляет состояние заказа и определяет необходимость отправки уведомления.

## Состав документации

- `requirements.md` — функциональные и нефункциональные требования.
- `business-rules.md` — бизнес-правила, ответственность систем и принципы формирования уведомлений.
- `api-contract.md` — структура взаимодействия систем через API.
- `diagrams/business-process.drawio.png` — диаграмма бизнес-процесса обработки события.
- `diagrams/order-statuses.drawio.png` — диаграмма статусной модели заказа и товара.

## Основные принципы

- Разделение статусов заказа и отдельных товаров.
- Отправка уведомлений только о значимых для пользователя событиях.
- Идемпотентная обработка повторных запросов.
- Сохранение событий, не обработанных из-за технических сбоев.
- Контроль ошибок и уведомление ответственных лиц о критических ситуациях.

## Статус документации

Требования и бизнес-правила подлежат уточнению в части политики повторных попыток, обработки накопленных событий и окончательной модели переходов между статусами.
